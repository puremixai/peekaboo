# 2026-10-12 工作日志

## 架构重构：Go 后端 + React 前端 + Docker（需求：「改造成go作为后端服务,react作为前端，docker镜像，dockercompose部署」）

### 为什么这么拆
原实现是一个 3.7 MB 的单文件 HTML（数据全内嵌、避让算法在浏览器里跑）。改成前后端分离后：
- **首屏体积从 3.7 MB 降到约 57 KB（gzip）**：点位列表 gzip 后 170 KB，评论改为点击弹窗时懒加载。
- **高德 Web 服务 Key 不再下发浏览器**，REST 调用全部走服务端。
- 避让算法移到 Go，可脱离浏览器单测，也便于做超时控制与后续缓存。

### 目录结构
```
server/                     Go 后端（只用标准库，无第三方依赖 → 离线可构建）
  main.go                   入口：装配依赖、优雅关闭
  internal/config/          环境变量配置（全部有默认值，可直接 go run）
  internal/geo/             等距圆柱近似的点线距离、米↔度换算
  internal/store/           三个 JSON 加载进内存 + CELL=0.01 空间网格索引
  internal/amap/            高德 REST 客户端（driving / inputtips）
  internal/planner/         避让算法（从原 JS 一比一移植）
  internal/httpapi/         路由、gzip、CORS、静态资源 + SPA 兜底
web/                        React + Vite 前端
  src/amap.js               JS API 2.0 加载器
  src/api.js  geo.js  icons.js  constants.js
  src/App.jsx               全局状态
  src/components/           MapView / PointPopup / Sidebar / Lightbox
Dockerfile                  三阶段：node 构建前端 → golang 构建后端 → alpine 运行（27.2 MB）
docker-compose.yml          build + 端口 + 环境变量 + 健康检查 + 资源限制
.env.example                高德 Key 等配置模板
```

### 接口设计
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 + 数据规模 |
| GET | `/api/config` | 前端启动配置（JS Key、默认半径、类型码等） |
| GET | `/api/points` | 全部 6288 个点位（831 KB，gzip 173 KB） |
| GET | `/api/points/{id}` | 单点位详情 + 最近 N 条评论（默认 20，`?limit=` 可调） |
| POST | `/api/plan` | 服务端跑完整避让算法，一次返回全部方案 |
| GET | `/api/tips?kw=` | 起终点输入提示（代理高德，Key 不外泄） |

### 算法移植验证（关键）
Go 版输出与 JS 版**逐条一致**：
基准 15.52 km（100 米内 18 个点位、15 个红点）→ 17.84 / 22.16 / **23.11 km 红点 0**。
容器内再测一次同样是 15.52 / 17.84 / 22.16 / 23.11。移植成功。

### 踩坑与修正
1. **Go nil 切片序列化成 `null`**：`append([]Area(nil), ...)` 在空时返回 nil。
   前端拿到 `null` 再 `len()` 就报错。统一改成 `append([]Area{}, ...)` / 显式初始化。
2. **走廊内橙色点位标记吞掉点击**：`near` 图层 zIndex 105 压在普通点位之上，
   且 `clickable: true` 但没绑事件 → 用户点橙色标记毫无反应。
   这是真实 bug（不只是测试问题），已补上 `m.on('click', () => openPoint(idx))`。
3. **热门点位评论全量下发**：最多的一条有 600 条评论，全量返回约 54 KB 且前端渲染 600 个 DOM 节点。
   改为默认只返回最近 20 条 + 总数，响应降到 2.3 KB，弹窗显示「600 条（显示最近 20 条）」。
4. **测试时序坑（非应用 bug）**：
   - `setZoomAndCenter` 默认是动画的，**时长随距离变化**（跨城区 5~6 秒），
     测试里必须传 `immediately=true`，否则算出的屏幕坐标是动画中间态。
   - 更隐蔽的：方案渲染时会调 `setFitView`（动画），**动画期间发出的 `setZoomAndCenter` 会被丢弃**。
     测试改成「设一次 → 校验 → 没到位再来」的循环才稳定。

### 前端弹窗方案变更（相比单文件版）
单文件版用 AMap 的 `InfoWindow`，踩过「一次性定位、事后改高度会断锚点」的坑。
React 版改成**地图容器内的绝对定位覆盖层**：用 `lngLatToContainer` 拿点位像素坐标，
地图 `moving`/`zoomchange`/`moveend` 时重算锚点，弹窗自己决定朝上还是朝下并限制高度。
完全由 React 掌控，不再受 AMap 定位行为影响。

### Docker 要点
- 三阶段构建；Go 用 `CGO_ENABLED=0 -trimpath -ldflags="-s -w"` 出静态小二进制。
- 运行阶段 alpine + ca-certificates（调高德 HTTPS 必需）+ tzdata（日志时区）。
- 非 root 用户运行；数据只读，不需要写权限。
- 健康检查用 busybox 自带的 wget，不额外装包。
- `.dockerignore` 显式列举要排除的文件（**不要用 `*.html` 这类通配**，
  可能误伤 `web/index.html`），并确保三个 JSON 不被排除。
- `.env` 与 `amap_key.txt` 都进 `.gitignore`，Key 只经环境变量注入容器，不落镜像层。
- 规划接口最长跑一两分钟，反代/网关超时要放宽（服务端 WriteTimeout 设成 150s + 30s）。
